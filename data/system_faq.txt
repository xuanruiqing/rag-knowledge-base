# 智能RAG问答系统 FAQ运维大全（超长完整版知识库）
# 本文件用于系统知识库测试、切片测试、向量检索测试、多文件混合检索、增量更新测试
# 内容涵盖：常见报错、部署问题、向量异常、切片原理、问答故障、模型调用、日志分析、运维排查

## 一、系统基础FAQ
Q1：什么是RAG智能问答系统？
A1：RAG智能问答系统是基于检索增强生成技术的私有知识库问答系统。区别于传统大模型，它不会使用公网训练知识，所有回答完全依赖用户上传的私有TXT文档内容。用户上传知识库文件后，系统自动完成加载、清洗、切片、向量化、入库，用户提问时检索相关片段，拼接上下文交给大模型生成答案，有效解决大模型幻觉、知识滞后、无法私有化部署的问题。

Q2：系统支持哪些文件格式？
A2：目前稳定支持 UTF-8 编码的 TXT 文件、Markdown 文件。PDF仅支持纯文本PDF，扫描版PDF为图片格式，需要OCR识别后才能入库。不支持Word、Excel、PPT等二进制文件，需要提前转为纯文本。

Q3：为什么必须使用UTF-8编码？
A3：Windows默认保存的ANSI/GBK编码会导致中文乱码、文本切片错乱、读取报错、向量化失败。所有知识库文件必须统一 UTF-8 编码，否则系统会抛出文件读取异常。

## 二、入库流程常见问题
Q4：什么是文档切片？为什么要切片？
A4：大模型与向量模型都有单次输入长度限制。完整长文本无法直接向量化，必须分割成固定长度的文本片段，这个过程叫切片（Chunk）。
切片目的：
1. 适配Embedding模型输入长度限制
2. 让每段向量语义更加聚焦
3. 提升检索精准度
4. 避免长文本语义混杂导致向量偏移

Q5：chunk_size 和 chunk_overlap 作用分别是什么？
A5：chunk_size 代表单切片最大字符长度，常规中文RAG推荐400–600。
chunk_overlap 代表相邻切片重叠字符数，一般设置为chunk_size的10%–20%。
重叠作用：防止完整语义被切分到两个切片边界，导致上下文丢失、检索不全。

Q6：切片太大有什么问题？
A6：切片过大，单段内容主题混杂，向量特征模糊，相似度检索不准，容易召回无关内容，增加幻觉概率。

Q7：切片太小有什么问题？
A7：切片过小，语义碎片化，单条切片信息不完整，无法独立回答问题，上下文断裂，召回结果无效。

Q8：什么是MD5增量入库？
A8：MD5是文件内容唯一指纹。系统每次入库前计算文件MD5，和数据库历史记录对比。
内容不变 → 跳过入库，节省算力和API费用
内容变更 → 删除旧向量，重新入库
文件删除 → 自动清理脏向量

Q9：修改文件名会不会触发重新入库？
A9：不会。MD5计算的是文件内容哈希，和文件名、创建时间、修改时间无关。仅改名字内容不变，不会重新入库。

Q10：反复运行入库脚本会重复生成向量吗？
A10：开启MD5增量机制后不会重复入库。没有MD5机制会无限重复生成向量，导致向量库爆炸、检索变慢、大量脏数据。

## 三、向量模型与检索问题
Q11：Embedding模型作用是什么？
A11：将自然语言文本转换成高维浮点向量。语义相似的文本向量距离更近，语义无关距离更远，实现语义检索。

Q12：为什么入库和检索必须用同一个Embedding模型？
A12：不同Embedding模型向量空间、映射规则、维度完全不同。混用模型会导致向量不匹配，检索完全失效。

Q13：什么是Top-K检索？
A13：用户提问向量化后，从向量库取出相似度最高的K条切片，K一般设置为3–5。Top-K过小容易召回信息不足，过大容易混入无关内容。

Q14：相似度阈值作用是什么？
A14：过滤低相似度垃圾召回。低于阈值的片段直接丢弃，不送入大模型。有效抑制幻觉，提高回答准确度。常规阈值0.4–0.7。

Q15：什么是脏向量？
A15：源文件修改、删除后，向量库残留的旧向量切片。脏向量会导致检索到过期内容、重复内容、错误内容，必须自动清理。

## 四、Reranker重排序知识点
Q16：Reranker和Embedding区别？
A16：Embedding是粗召回，速度快、语义弱；Reranker是精细排序，输入问题+文档配对打分，语义理解更强，用来优化粗召回结果。

Q17：为什么需要Reranker？
A17：向量相似度匹配是数学匹配，不是语义匹配，经常出现向量相似但语义无关的情况。Reranker可以过滤误召回内容，大幅提升RAG精度。

## 五、系统报错与运维排查
Q18：报错 FileNotFoundError？
A18：文件路径不存在、文件被删除、目录写错、相对路径找不到文件。系统会捕获异常并跳过当前文件，不影响整体入库。

Q19：报错 API 请求超时？
A19：网络波动、模型接口限流、网络延迟过高。程序捕获异常后记录error日志，等待下次运行重试。

Q20：中文全部乱码？
A20：文件编码不是UTF-8，重新另存为UTF-8即可解决。

Q21：检索结果为空？
排查步骤：
1. 确认文件是否成功入库
2. 确认是否开启增量更新导致文件被跳过
3. 检查问题语义是否和知识库匹配
4. 检查相似度阈值设置是否过高
5. 检查Embedding模型是否一致

Q22：检索结果很多无关内容？
A22：切片不合理、没有Reranker、阈值过低、向量库存在大量脏向量。

## 六、日志系统说明
Q23：logger.info 是什么日志？
A23：记录系统正常运行信息，如：文件加载成功、切片完成、向量入库、旧向量删除、会话创建成功。

Q24：logger.error 是什么日志？
A24：记录所有异常报错，如读取失败、接口报错、数据库异常、文件异常，用于运维排查。

Q25：为什么要用try-except捕获异常？
A25：防止单个文件报错导致整个系统崩溃，实现单文件故障隔离，保证整体流程稳健运行。

## 七、数据库会话知识
Q26：SQLite数据库作用？
A26：保存文件MD5指纹、用户会话ID、多轮对话记录、问答时间，实现持久化存储。

Q27：什么是会话ID session_id？
A27：每一次对话独立唯一ID，用于区分不同用户、不同对话上下文，实现多轮问答连续对话。

## 八、RAG优化进阶知识
Q28：如何提升RAG准确率？
优化方案：
1. 规范文档清洗，去除无效内容
2. 合理调优chunk_size与overlap
3. 开启Reranker重排序
4. 设置合理相似度阈值
5. 开启MD5增量更新，清除脏向量
6. 优化Prompt提示词约束大模型

Q29：如何彻底解决幻觉？
A29：无法100%消除，但可以大幅抑制：
1. 严格限制只使用检索到的文档回答
2. 无相关内容统一回复暂无相关信息
3. 过滤低相似度内容
4. 加强prompt约束
5. 开启重排序过滤无关片段

## 九、工程化项目亮点总结
1. 支持大批量TXT文档批量入库
2. 完整MD5增量更新机制，智能跳过无变更文件
3. 自动清理脏向量，避免数据冗余
4. 完整日志分级记录，可运维、可排查
5. 全链路异常捕获，程序高可用
6. 配置文件解耦，无硬编码
7. 支持相似度阈值过滤+Reranker双重优化
8. 支持多轮对话持久化
9. 标准化切片策略，适配中文知识库
