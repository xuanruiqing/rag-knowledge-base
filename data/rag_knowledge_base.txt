# RAG检索增强生成完整工程化知识库
检索增强生成（Retrieval-Augmented Generation，简称RAG），是当前大模型落地最主流的方案。原生大模型的知识是训练时固化在权重里面的，存在知识滞后、无法接入私有文档、容易编造虚假信息也就是幻觉等缺陷。RAG的核心思路就是不改动大模型权重，在用户提问的时候，从外部私有知识库检索相关资料，把资料拼进prompt交给大模型，让大模型依据参考资料回答问题。

RAG整体分为索引构建阶段和在线推理检索阶段。

索引构建阶段，也叫文档入库流水线，是离线执行的任务：
第一步，文档加载。支持各类文档格式，包括txt、markdown、Word、PDF。普通文本PDF可以直接提取文字；扫描版PDF是图片形式，需要OCR光学字符识别才能提取文本内容。
第二步，文本清洗。原始文档里经常有多余换行、空格、特殊符号、页眉页脚，需要预处理，去除无效字符，避免干扰向量编码。
第三步，文本切片Chunk。这一步是RAG效果非常关键的一环。把长文档切分成多个较短的文本片段。两个核心参数：chunk_size 是单个切片最大字符长度，chunk_overlap是切片之间重叠字符数。重叠的目的是保证一个完整语义不会被切在两个切片边界而丢失上下文。
第四步，Embedding向量化。调用向量模型，把文本片段转换成固定维度的浮点向量。语义相近的文本，向量在高维空间距离更近。目前可用的向量模型有火山方舟Embedding、阿里百炼Embedding、bge系列开源模型。
第五步，向量入库。将向量、原始文本片段、元数据存入向量数据库。元数据一般保存文件名、文件路径、MD5指纹、切片序号。向量数据库常见选型：Chroma、FAISS、Milvus、Qdrant。

增量更新机制（MD5文件指纹）：
每次入库前读取本地文件，计算MD5哈希值。MD5相当于文件的唯一指纹，文件内容只要改动一个字符，MD5值就会完全变化。
系统会把已经入库文件的MD5记录在SQLite数据库中。
逻辑：
1. 如果本地文件MD5和数据库记录一致：文件没有修改，直接跳过向量化，节省API调用费用和时间。
2. 如果MD5不一致：文件被修改，需要先在向量库删除该文件对应的全部旧向量切片，再重新切片、向量化、写入新向量。
3. 如果本地文件已经删除：自动清理向量库里面属于该文件的所有脏向量。
这个机制在工程项目里非常重要，避免重复入库产生大量冗余脏向量，也是简历项目亮点。

在线推理检索阶段，用户提问时实时执行：
1. 用户Query预处理：清理问句，部分场景可以做查询改写，把简短问题扩展成更利于检索的描述。
2. Query向量化：把用户问题通过同一个Embedding模型转为向量。注意：检索和入库必须使用同一个Embedding模型，否则向量空间不一致，召回结果完全失效。
3. 向量相似度检索：在向量库里面计算向量距离，取出Top-K个相似度最高的文本切片。
4. Reranker重排序（可选优化点）：Embedding召回是粗召回，会召回一些向量数值接近但是语义无关的片段。Reranker模型接收【问题+候选切片】成对输入，重新打分，过滤掉无关文档，提升召回质量，是RAG优化的核心加分项。
5. 相似度阈值过滤：设置一个阈值，低于阈值的切片直接丢弃。如果所有召回片段都低于阈值，代表知识库没有相关内容，直接告诉用户暂无相关资料，可以有效抑制幻觉。
6. 构造Prompt上下文：把筛选后的参考片段，连同用户问题组装提示词，交给LLM。
7. LLM生成回答：大模型严格基于提供的参考文档回答，参考资料没有的信息禁止编造。可以开启流式输出，逐字返回回答。

RAG常见问题与调优方案：
1. 幻觉问题：即使RAG也会幻觉。成因包括召回无关文档、参考信息不足、大模型强行编造。解决手段：相似度阈值过滤、Reranker过滤、Prompt约束、增加引用溯源。
2. Chunk切片参数调优：
chunk_size太大：单段包含多个主题，向量表征混杂，召回不准。
chunk_size太小：语义被切碎，单独切片信息残缺，缺少完整上下文。
一般中文场景chunk_size取300~800字符，overlap设置为chunk_size的10%~20%。
3. 召回效果差：排查方向：embedding模型前后不一致、清洗不到位、切片不合理、向量库距离度量选错、没有做reranker。
4. 知识库更新慢：引入MD5增量更新，避免全量重建向量库。

工程化落地规范：
1. 配置解耦：所有超参数、API密钥、模型接入点全部放到.env环境配置文件，代码里面不写死硬编码。方便切换环境、更换模型。
2. 日志模块：使用Python logging，替代print。对文件读取、向量入库、删除向量、异常报错、检索请求做完整日志记录，方便问题排查。日志分级：info正常信息，error异常错误。
3. 异常捕获：全链路增加try-except捕获。文件读取异常、网络API超时、向量库读写异常都需要捕获，记录日志，程序不会直接崩溃退出。
4. 会话管理：使用SQLite数据库持久化多轮对话历史，支持多用户会话隔离，保存对话ID、历史消息、会话创建时间。
5. 代码模块化：文档加载模块、切片模块、embedding模块、向量库模块、对话模块分开，结构清晰，方便维护。

RAG项目面试高频问题：
问：为什么入库和检索必须同一个Embedding模型？
答：每个Embedding模型映射规则不一样，不同模型生成向量不在同一个向量空间，向量距离没有意义，召回结果不可用。

问：MD5增量更新的原理是什么？如果只是修改文件名，MD5会变吗？
答：MD5计算的是文件内容哈希，只修改文件名，文件内容不变，MD5不会改变，不会触发重新入库。

问：Reranker和Embedding的区别？
答：Embedding是粗召回，把文本映射向量，速度快；Reranker是精细打分，输入问题和文档对，语义理解更强，但是速度慢，一般只对Top-K候选做二次筛选。

问：什么是脏向量？
答：源文件被删除或者修改之后，向量库里面残留的旧切片向量，不会自动消失，如果不清理，检索的时候会召回过期、无效内容。

RAG应用场景：企业私有知识库、产品手册问答、项目文档智能检索、个人知识库、客服智能问答。
